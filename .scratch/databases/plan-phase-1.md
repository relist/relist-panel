# Databases phase 1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Admin can create, start, stop, restart, rename, update, repair and
delete a panel-managed Postgres, MySQL, MariaDB or Redis **Database** from a new
**Data → Databases** page. The Admin can copy its connection details into any
Compose. Server migration moves Databases.

**Architecture:**
- **Package.** A new `internal/databases` package owns the store, the engine
  drivers, and a `Service` that reconciles each Database's container with its
  stored record. It follows the Registry pattern (`internal/registry`,
  ADR-0033).
- **Engine API.** `internal/dockerexec` implements the package's `Host` port over
  the Engine API.
- **HTTP.** `internal/databases/http.go` serves `/api/databases`, which is
  Admin-only by omission from `authz.Routes`.
- **Frontend.** The page lives in `web/src/pages/`.

**Tech Stack:**
- Go 1.x with `database/sql` + SQLite (goose migrations).
- Docker Engine API over the unix socket.
- React 19, antd 6.5.1, react-router 8, vitest.
- Playwright for e2e.

**Spec:** `.scratch/databases/spec.md`. Phase 1 = "Core" in its Phases section.
Phases 2–4 (backups, schedules and destinations, query panel) are **not** part
of this plan.

## Global Constraints

- Database records are never stored by name on the host. All host objects derive from the ID: container `relist-db-<id>`, volume `relist-db-<id>`, labels `relist.database.id=<id>` and `relist.database.hash=<hex>`.
- No host port is ever published for a Database container.
- Network: `relist-network` only, with alias `<slug>.db.internal` in addition to the container name. The alias is skipped with a warning when the slug is the fallback `x` or longer than 63 characters.
- Restart policy `unless-stopped`. Log config `json-file` with `max-size=10m`, `max-file=5` (ADR-0028 default service log cap).
- Password: 32 random bytes, base64url without padding (43 chars). Generated by the panel and never chosen by the user. It is stored in plain text in `databases.password`.
- Every `/api/databases*` route is Admin-only. Each must be added to `adminOnly` in `internal/authz/routescan_test.go`, and every route that changes something must be added to `authz.Actions`.
- Revealing the password records `audit.SecretRead(ctx, []string{"password"})`.
- Engines and versions (exact tags):
  - postgres: `18` (default), `17`, `16`
  - mysql: `8.4`
  - mariadb: `11.8` (default), `11.4`
  - redis: `8` (default), `7.4`
- Images are pinned by tag and pulled from Docker Hub without a login. This is the fifth image the panel pulls itself, recorded in the new ADR.
- Never edit a committed migration. Add `internal/migrations/00041_databases.sql`. If `00041` is taken on main when you start, use the next free number.
- Commit messages: Conventional Commits, no scope, ending with the repo's `Co-Authored-By` line.
- Frontend: read `https://ant.design/llms.txt` and the antd pages you use before writing UI. Follow `docs/GUIDELINES.md`.

## Review Focus

1. **Postgres 18's image moved its data directory.** The volume must mount at `/var/lib/postgresql` for 18+ and at `/var/lib/postgresql/data` for ≤17. A wrong mount on 18 makes the container refuse to start, or writes the data outside the volume. *Test:* Task 2 `TestPostgresDataPath`. Task 9's live check creates a postgres 18 and a postgres 16, restarts both, and confirms the data survives.
2. **A missing volume must never be silently recreated.** A Database that has started once and whose volume is gone must report `volume_missing`, and Reconcile must not create anything. *Test:* Task 3 `TestReconcileVolumeMissingDoesNothing`.
3. **The password contains `-` and `_`, and the URL must still parse.** Usernames and database names may need percent-encoding too. *Test:* Task 2 `TestURLEncodesCredentials` parses the produced URL with `net/url` and gets the password back.
4. **Rename must not restart the Database.** Only the network alias changes. *Test:* Task 3 `TestRenameRealiasesWithoutRecreate` asserts no `Create` and no `Restart` on the fake host.
5. **The migration lock and a stopped Database.**
   - Reconcile must not start a Database while a server Migration holds the lock.
   - Resume must start only the Databases whose desired state is `running`.

   *Tests:* Task 3 `TestReconcileSkipsWhileLocked`. Task 7 `TestResumeStartsWantedDatabasesOnly`.

  // ports.go
  const Network = "relist-network"
  const IDLabel, HashLabel = "relist.database.id", "relist.database.hash"
  func ContainerName(id int64) string // "relist-db-<id>"
  func VolumeName(id int64) string    // "relist-db-<id>"
  func Alias(slug string) string      // "<slug>.db.internal", "" when skipped

      Name, Volume, Image, DataPath string
      Env, Cmd, Healthcheck         []string
      Alias                         string // "" = none
      MemoryBytes, NanoCPUs         int64
      Labels                        map[string]string
  }
  type ContainerState struct {
      Exists, Running bool
      Health          string // "", "starting", "healthy", "unhealthy"
      Hash            string
      ImageID         string
      Aliases         []string // on relist-network
  }
  type Host interface {
      EnsureImage(ctx, ref string) error            // pull when absent
      PullImage(ctx, ref string) (imageID string, err error) // always pull
      ImageID(ctx, ref string) (string, error)

      Store  *Store
      Host   Host
      Locked func(ctx context.Context) bool // server Migration lock; nil = never
      Now    func() time.Time
  }
  type CreateInput struct{ Name, Engine, Version string; MemoryMB int64; CPUs float64 }
  type View struct {
      Database
      Status   string
      Warnings []string // e.g. alias skipped

  func New(d Deps) *Service
  func (s *Service) Create(ctx, in CreateInput) (Database, error) // inserts, then reconciles in the background

  func (s *Service) Stop(ctx, id int64) error
  func (s *Service) Restart(ctx, id int64) error
  func (s *Service) Rename(ctx, id int64, name string) error

  func (s *Service) Logs(ctx, id int64, tail int) (string, error)
  func (s *Service) ReconcileAll(ctx) error           // every Database; errors are stored per Database, and the first is returned
  func (s *Service) StopAll(ctx) error                // Migration: stop every container, leave Desired as is
  func (s *Service) StartWanted(ctx) error            // Migration resume: Reconcile each Desired=running
  func (s *Service) Volumes(ctx) ([]string, error)    // Migration: volume names of Initialized Databases

**Rules the tests pin:**
- **Name**: trimmed, 1–63 characters; its slug comes from `slug.Slugify`. A slug conflict with another Database → `ErrDuplicateName`.
- **Hash**: hex sha256 over `Image`, `DataPath`, `Env` (with the password replaced by its sha256), `Cmd`, `Healthcheck`, `MemoryBytes` and `NanoCPUs`. **Not** the alias, so rename never recreates.
- **Reconcile of one Database**, under a per-ID mutex:
  - If `Locked` → return `ErrLocked` and touch nothing. `ErrLocked` is never stored as `LastError`; `ReconcileAll` treats it as a skip and returns nil.
  - `StopAll` and `StartWanted` are the Migration's own calls and **ignore `Locked`**. They run while the lock is held: on the old host at stop and resume, and on the new host from `BeforeDeploy`.
  - If `Desired=stopped`: stop a running container; nothing else.
  - If `Desired=running`:
    - **container missing:**
      - `Initialized` and the volume is gone → set nothing on the host; Status becomes `volume_missing`;
      - otherwise `EnsureImage`, `Create`, then `SetInitialized`.
    - **hash differs** → `Create` (recreate on the same volume).
    - **not running** → `Start`.
    - **alias missing** from `Aliases` → `Realias`.
  - A failure stores `LastError`; a success clears it.
- **Status order**:
  1. background work in flight → `creating`;
  2. `LastError` → `error`;
  3. `volume_missing`;
  4. `Desired=stopped` → `stopped`;
  5. missing or hash differs → `drift`;
  6. not running → `stopped`;
  7. health `starting` / `unhealthy` → that;
  8. else `running`.
- **Start / Stop / Restart** set `Desired` first, then act through the Host.
- **Delete**: `Remove`, then `RemoveVolume`, then `Store.Delete`. Phase 1 has no Backups, so the row is removed. Phase 2 changes this.

## Spec deltas this plan makes (already applied to `spec.md`)

- **Pulls.** Images are pulled over the Engine API with no registry login. They are Docker Hub official images. The spec's "External registries apply" line is removed.
- **Logs.** Phase 1 shows a tail with Refresh, as Compose logs do. Follow is dropped.
- **Rename.** It re-aliases on `relist-network` without restarting. The alias is outside the hash.
- **Delete in phase 1** removes the row. The `deleted` tombstone arrives in phase 2 with Backups.
- **Server migration** always moves Database volumes and stops Databases first. This replaces the spec's "add to inventory, or block" open choice.
- **Versions** are pinned as in Global Constraints. Postgres is 18/17/16, not 17/16/15. MariaDB is 11.8/11.4. Redis is 8/7.4.
