# Spec — Panel-managed Traefik static config, applied with self-heal

Date: 2026-11-04.
Status: open — branch claude/traefik-static-config

## Problem

Traefik's static config is about 20 `command:` flags in the Install file
(`docker-compose.yml`), plus two `.env` keys interpolated into them
(`RELIST_ACME_EMAIL`, `TRAEFIK_TRUSTED_IPS`). Two problems follow from this:

- **Changing a setting needs SSH.** To trust a proxy (for example Cloudflare), change the
  log level or turn the Access log on or off, the operator edits `.env` or
  `docker-compose.override.yml` on the host and runs `docker compose up -d`. A mistake
  there stops Traefik, which takes every Domain and the panel down with it. Nothing checks
  the change first and nothing puts the old config back.
- **The Install file is hard to read.** Flags that the panel needs in order to work sit
  next to flags that are only defaults, with nothing to tell them apart. A `command:` list
  in an override replaces the whole list (ADR-0024 evidence), so one changed flag means
  copying all of them.

Traefik takes static config from exactly one source: a file, CLI flags or env. A file
therefore has to replace all of the flags at once, not some of them.

## Goal and success criteria

- Traefik reads one file, `/etc/traefik/traefik.yml`, which the panel generates. The
  Install file's Traefik `command:` is the single flag
  `--configfile=/etc/traefik/traefik.yml`.
- The generated file is **base + Traefik override**:
  - The base is embedded in the binary. It holds what the panel needs, as **locked keys**,
    and defaults the operator may change.
  - The Traefik override, `<data dir>/.traefik/static/traefik.override.yml`, is the
    operator's. The panel never overwrites it except when the operator saves.
- On the Traefik page the operator edits the Traefik override through a five-field form
  (**Settings**) or as raw YAML (**Advanced**). Both edit the same draft.
- **Apply** validates the draft and dry-runs it in a throwaway Traefik. It then backs up
  the current files, writes the new ones and restarts Traefik. For 60 s it watches Traefik;
  if Traefik is not healthy, it restores the backup and restarts again. The result is
  shown in a modal, including after the browser reconnects.
- A fresh install and an install updated from 0.0.2 take the same path. A one-shot
  `traefik-config` service in the Install file generates the file on every
  `docker compose up`, before Traefik starts. The update needs no manual step, and the
  0.0.2 Updater can perform it.
- The Access log is **off by default** on a fresh install, with a retention default of
  90 days. An install updated from 0.0.2 keeps the Access log it has.
- The legal warnings (an Access log retention under 90 days, the Access log off) are
  removed.
- Contributor docs are organised by system. A new `docs/README.md` index links to one guide
  page per system, starting with `docs/guide/traefik.md`.

## Out of scope / follow-up

- **Always replacing the Install file.** ADR-0024's merge of an edited
  `docker-compose.yml` stays as it is. The rule "edit the override, not the Install file"
  is documented more clearly; it is not enforced.
- **Guide pages for the other systems** (Panel update, Migration, Deployments, Domains, …).
  This spec creates the index and the Traefik page. The rest is a separate piece of work.
  Until then the index links each of those systems to its ADRs.
- Form fields for timeouts, HTTP/3 (it needs UDP 443 in `ports:`, which the panel cannot
  set), the Traefik dashboard and API, metrics and tracing. All of these can be set in
  Advanced.
- Fetching Cloudflare's IP ranges at runtime. The ranges are a constant in the code, and
  newer ranges are typed into Trusted proxies by hand.
- A global HTTP→HTTPS redirect. Each Domain already sets its own (`internal/domains/labels.go`).
- Panel-managed dynamic config beyond Certificates.

## Domain changes

- `CONTEXT.md` gains:

  **Traefik override**:
  The operator's part of Traefik's static config, `<data dir>/.traefik/static/traefik.override.yml`,
  edited on the Traefik page. The panel merges it over the base into the generated
  `traefik.yml` that Traefik reads (ADR-0028).
  _Avoid_: Traefik config (ambiguous between base, override and generated file), traefik.yml
  (that is the generated file).

  **Traefik apply**:
  Writing a new Traefik override and restarting Traefik with self-heal: validate, dry-run,
  back up, write, restart, watch for 60 s, and roll back on failure (ADR-0028).
  _Avoid_: Reload (Traefik cannot reload static config; this is a restart).

- `CONTEXT.md` **Install override** entry gains a sentence: the Traefik override is the
  equivalent for Traefik's static config.
- ADR-0028 records the decision:
  - base + override, generated by a one-shot service, instead of flags or a single editable file;
  - self-heal on apply.
  _Amends ADR-0027_, because the Access log becomes opt-in.

## Files on disk

```
<data dir>/.traefik/
  acme.json, dynamic/, access/       unchanged; mounted at /letsencrypt
  static/                            new; mounted at /etc/traefik (read-only)
    traefik.yml                      generated: base + override. Written by the panel and
                                     traefik-config, read by Traefik at start only.
    traefik.override.yml             the Traefik override (the operator's)
    history/<UTC time>-<id>/         the last 10 backups: traefik.override.yml + traefik.yml
    apply.json                       the last Traefik apply: state, result, log
    .dryrun-<id>/traefik.yml         candidate for a dry-run; removed afterwards
```

- Every write goes to a temp file, which is then renamed over the target. A directory is
  mounted, not a file: a missing single-file bind source becomes a directory, and a rename
  would leave the container on the old inode.
- `traefik.yml` starts with the comment
  `# Generated by relist-panel from its base and traefik.override.yml. Do not edit: changes are overwritten.`
- A Migration carries `static/` with the data dir. Nothing new is needed for it.

## Base and merge

The base is `internal/traefikconfig/base.yml`, embedded in the binary. It holds two kinds of
key.

**Locked keys.** The panel needs these. If the override sets a different value, Apply is
refused and the key is named.

| Key | Value | Why |
|---|---|---|
| `entryPoints.web.address` | `:80` | ports and the HTTP challenge |
| `entryPoints.websecure.address` | `:443` | ports; the panel router uses `websecure` |
| `providers.docker.exposedByDefault` | `false` | only labelled Services are routed |
| `providers.file.directory` | `/letsencrypt/dynamic` | uploaded Certificates (ADR-0022) |
| `providers.file.watch` | `true` | the same |
| `certificatesResolvers.letsencrypt.acme.storage` | `/letsencrypt/acme.json` | Domains' certificates |
| `certificatesResolvers.letsencrypt.acme.httpChallenge.entryPoint` | `web` | the same |
| `log.noColor` | `true` | the Traefik page parses the log |
| `log.format` | `common` | the same |
| `accessLog.filePath` | `/letsencrypt/access/access.log` | rotation (ADR-0027) |
| `accessLog.format` | `json` | the same |
| `accessLog.fields.headers.defaultMode` | `drop` | no Authorization or Cookie in the file |

**Defaults.** The override may change these:

- `entryPoints.{web,websecure}.transport.respondingTimeouts.readTimeout: 3600s`;
- `log.level: INFO`;
- `accessLog.fields.headers.names.User-Agent: keep`;
- `GOMEMLIMIT` stays in the Install file's `environment:`, because it is not static config.

**The `accessLog` section is conditional.** The base's `accessLog` keys enter the generated
file only when the override has an `accessLog` key, whatever its value (`accessLog: {}`
turns it on). Without that key the generated file has no `accessLog`, and Traefik writes
none.

**Merge rules:**

- Keys match case-insensitively. Traefik ignores case (probe 2026-11-04: `forwardedheaders`,
  `trustedips` and `readTimeOut` all load). The generated file uses the base's spelling;
  for keys not in the base it uses the override's spelling.
- Maps merge recursively, with the override winning. Lists and scalars from the override
  replace the base's.
- The override may add anything else, for example another entrypoint, a resolver, `api`,
  `metrics` or `experimental`.
- A top-level override key that is not a Traefik static section is refused by name.
  Traefik silently ignores unknown top-level keys, but fails on unknown nested ones
  (probe 2026-11-04). The list is the top-level fields of Traefik v3.7's static
  configuration, kept in `internal/traefikconfig/sections.go`.

## Form fields (Settings)

Each field reads and writes one place in the Traefik override. The edit is server-side on a
`yaml.v3` node tree, so comments and key order in the override survive.

| Field | Override key(s) | Notes |
|---|---|---|
| ACME email | `certificatesResolvers.letsencrypt.acme.email` | may be empty (ADR-0013) |
| Trusted proxies | `entryPoints.web.forwardedHeaders.trustedIPs` and the same under `websecure` | one IP/CIDR per line; both entrypoints get the same list; each entry is validated as an IP or CIDR |
| Trust Cloudflare | the same lists | adds or removes Cloudflare's ranges (`internal/traefikconfig/cloudflare.go`, with the source URL and date). It reads as on when every range is present |
| Log level | `log.level` | `ERROR`, `WARN`, `INFO`, `DEBUG` |
| Access log | presence of `accessLog` | off removes the key; on adds `accessLog: {}` |

- When the two entrypoints' lists differ (someone edited them in Advanced), the form shows
  the `websecure` list. It warns: "web and websecure differ; saving here makes them the
  same".
- The Retention card (ADR-0027) is unchanged except that its under-90-days warning is
  removed. Retention still defaults to 90 days and applies whenever files exist.

## Install compose (`docker-compose.yml`)

```yaml
traefik-config:
  container_name: relist-traefik-config
  image: ${RELIST_PANEL_IMAGE:-ghcr.io/relist/relist-panel:latest}
  command: ["traefik-config"]
  restart: "no"
  environment:
    RELIST_DATA_DIR: ${RELIST_DATA_DIR:-/var/lib/relist-panel}
    RELIST_ACME_EMAIL: ${RELIST_ACME_EMAIL:-}
    TRAEFIK_TRUSTED_IPS: ${TRAEFIK_TRUSTED_IPS:-}
  volumes:
    - ${RELIST_DATA_DIR:-/var/lib/relist-panel}:${RELIST_DATA_DIR:-/var/lib/relist-panel}
    - /var/run/docker.sock:/var/run/docker.sock:ro
  network_mode: none
  logging: {driver: json-file, options: {max-size: "1m", max-file: "2"}}

traefik:
  command: ["--configfile=/etc/traefik/traefik.yml"]
  depends_on:
    traefik-config: {condition: service_completed_successfully}
  volumes:
    - ${RELIST_DATA_DIR:-/var/lib/relist-panel}/.traefik:/letsencrypt
    - ${RELIST_DATA_DIR:-/var/lib/relist-panel}/.traefik/dynamic:/letsencrypt/dynamic
    - ${RELIST_DATA_DIR:-/var/lib/relist-panel}/.traefik/static:/etc/traefik:ro
    - /var/run/docker.sock:/var/run/docker.sock:ro
  # environment, ports, networks, limits, logging, restart: unchanged
```

- The two `.env` keys stay only as seeds for the first override. The README says so, and
  says that afterwards the Traefik page is where they are changed.
- `release/invariants.json`:
  - drops the three Traefik `service-command-has` flags;
  - adds `service-command-has traefik --configfile=/etc/traefik/traefik.yml`;
  - adds `service-mount traefik <data dir>/.traefik/static → /etc/traefik read_only`.

  Both kinds are known to 0.0.2. If the source cannot be expressed with the data-dir
  variable, the mount invariant is dropped, and the plan says which one was used.
- `release/manual-steps.json` is emptied. Its three steps were for installs from before
  the Install script, which update by hand anyway.

## `relist-panel traefik-config`

This runs on every `up`, before Traefik starts.

1. If `static/traefik.override.yml` is missing, create it:
   - **From `.env`** (a fresh install, and an update from 0.0.2): write the ACME email
     from `RELIST_ACME_EMAIL` and the trusted IPs from `TRAEFIK_TRUSTED_IPS` if either
     is set. Add `accessLog: {}` only when `<data dir>/.traefik/access/` already holds a
     file, which means an older Traefik was writing the Access log.

     Compose recreates Traefik *before* it runs `traefik-config` (probe 2026-11-04), so
     on an update the only Traefik left already has `--configfile`, and the old flags
     cannot be read. 0.0.2's flags took their values from those same two `.env` keys,
     and 0.0.2 always had the Access log on, so the result is the same.
   - **From the Traefik's flags**, only when the Install's Traefik still runs on flags
     (no `--configfile` among its args): read them with the existing `TraefikDocker.Args`.
     Convert each `--a.b.c=v` to a nested key, matching case-insensitively. Comma lists of
     known list fields become YAML lists. Skip flags whose value equals the base's, and
     `--configfile`. Write any flag that cannot be converted as a comment line
     `# not converted: --flag=value`. Keep `accessLog: {}` if `--accesslog=true`.
2. Generate `traefik.yml` from the base and the override.
3. If the override cannot be parsed or merged, keep the existing `traefik.yml` and log
   why. Write the reason to `apply.json` as a `traefik-config` warning, which the Traefik
   page shows.
4. Exit 0 in every case except one: no usable `traefik.yml` exists and none can be
   written. Probe 2026-11-04: a failing one-shot service makes `up` exit 1, which a Panel
   update treats as a failure.

The same binary and image as the panel run this service. A Panel update rollback therefore
regenerates the file with the old base.

## Traefik apply

The same flow runs for **Apply** (new override), **Restore** (a history entry) and
**Restart** (same files).

| # | Step | On failure |
|---|---|---|
| 1 | Lock: one Traefik apply at a time; refused while a Panel update or the Migration lock is on | 409 / 503, nothing changed |
| 2 | Validate: YAML parses, no locked key changed, top-level keys known, trusted IPs valid; `revision` (sha256 of the current override) matches | 400 with the key and line / 409; nothing changed |
| 3 | Dry-run: `docker run --name relist-traefik-dryrun-<id> --network none --tmpfs /letsencrypt -v <static>/.dryrun-<id>:/etc/traefik:ro <the running Traefik's image>`. Pass when it is still running after 5 s and its log has no `Command error`. Always removed | refused, dry-run log shown, nothing changed |
| 4 | Back up the current override and `traefik.yml` to `history/`; prune to 10 | refused, nothing changed |
| 5 | Write the override and `traefik.yml` | restore the backup, refused |
| 6 | Read `RestartCount`, then `docker restart relist-traefik` | roll back |
| 7 | Watch for up to 60 s, every 2 s | roll back |
| 8 | Healthy: record the generated file's sha256 and Traefik's `StartedAt` in `apply.json`, and unlock | — |

A dry-run with no socket and no network starts normally from the base's config, and exits
1 with `field not found` on an unknown nested key (probe 2026-11-04).

**Healthy (step 7):** the Container is running, its `RestartCount` is unchanged, and the
panel's `/healthz` answers through Traefik for `RELIST_DOMAIN`. The check reuses
`PanelUpdaterHost.Healthz` (the Traefik IP, with Host and SNI).

**Failed at once:** the Container has exited, its `RestartCount` has grown, or its log since
the restart has `Command error`.

**Failed at 60 s:** `/healthz` has not answered.

**Not a failure:** other `ERR` lines, such as ACME rate limits or DNS not pointing here.
They are shown in the result.

**Rollback:** write the backup back, restart, and watch with the same rules. The result is
`rolled-back` if that works and `rollback-failed` if not. Either way the run stops there;
it never retries in a loop.

**States in `apply.json`:**
`validating → dry-run → writing → restarting → checking → ok`, or
`… → rolling-back → rolled-back | rollback-failed`, or `refused` before anything was
written. Each run records its id, the user, the start and end times, the kind
(apply/restore/restart), the backup name, the reason, and the last 500 lines of Traefik's
log since the restart.

**A panel restart mid-run.** At start, a non-terminal state resumes:

- before `writing`, the run is marked `refused`;
- from `writing` to `checking`, it watches again and rolls back on failure;
- in `rolling-back`, it finishes the rollback.

**Interactions:**

- Deployments keep running during an apply. They change labels and `dynamic/` only.
- The Panel update quiesce waits for a running Traefik apply before it writes `ready`, as it
  waits for the Deployment queue.
- Restarting Traefik drops every Domain and the panel for a few seconds. The confirm modal
  says so.

**Pending restart.** The page shows "Config changed since Traefik started — Restart to
apply" when `traefik.yml`'s sha256 differs from the one recorded at the last healthy start.
With no record, it compares the file's mtime with Traefik's `StartedAt`. This happens when
`traefik-config` wrote a new base on an `up` that did not recreate Traefik.

## API

Every route is under the existing authenticated API. Writes are refused under the update
and Migration locks, as other writes are.

| Route | Does |
|---|---|
| `GET /api/traefik/config` | `{override, base, effective, form, revision, pendingRestart, warnings, lastApply}` |
| `POST /api/traefik/config/preview` | body `{override}` or `{form, override}` → `{override, effective, form, diff, errors[], warnings[]}`; saves nothing |
| `POST /api/traefik/config/test` | body `{override}` → validate and dry-run → `{ok, errors[], log}` |
| `POST /api/traefik/config/apply` | body `{override, revision}` → `202 {id}`, `400`, `409` or `503` |
| `GET /api/traefik/config/apply` | the last run from `apply.json` |
| `POST /api/traefik/config/apply/ack` | marks the last run seen, so its modal does not reopen |
| `POST /api/traefik/restart` | Restart through the same flow → `202 {id}` |
| `GET /api/traefik/config/history` | `[{name, at, user, kind, result}]` |
| `POST /api/traefik/config/history/{name}/restore` | Restore through the same flow → `202 {id}` |

- `{name}` is checked against the history name pattern before any file is opened, as Access
  log downloads are.
- `errors[]` items are `{key, line, message}`. `warnings[]` covers unconverted flags, the two
  entrypoint lists differing, and the last `traefik-config` problem.

## Comments

Probes on 2026-11-04 against `traefik:v3.7` (3.7.13) and the host's Docker Compose:

- With `--configfile`, other CLI flags are ignored. With the file missing, the CLI flags are
  used. Bad YAML exits 1. `${VAR}` in the file is not expanded.
- Unknown nested keys exit 1 (`field not found, node: <key>`). Unknown top-level keys
  (scalar or map) are ignored silently. Keys are case-insensitive.
- `/etc/traefik/traefik.yml` is loaded with no flag at all. The spec keeps the flag anyway,
  for readability and for the invariant.
- A one-shot service with `depends_on: service_completed_successfully`:
  - `up` waits for it, and it reruns on every `up` without restarting an unchanged Traefik;
  - when it exits 1, `up` exits 1 and the running Traefik stays;
  - `config --hash '*'` lists it.
- A directory bind mount and an atomic rename on the host, followed by `docker restart`:
  Traefik reads the new file.
- A dry-run with `--network none`, `/letsencrypt` on tmpfs and no Docker socket stays running
  with a base-like config.
- Not probed yet (plan task): the 0.0.2 Updater end-to-end with the new Install file.
