# The panel runs Databases as its own containers, one per Database

Every Compose that needed Postgres, MySQL, MariaDB or Redis carried its own database Service, so backups, queries and updates were the operator's problem (`.scratch/databases/spec.md`). The panel now runs Databases itself, which withdraws ADR-0001's non-goal "No database-as-a-service".

**Decision:** A **Database** is a typed, panel-managed entity, host-wide and Admin-only, run through the Engine API the way the Registry is (ADR-0033).
- **Not a Compose.** One Database is one container `relist-db-<id>` and one named volume `relist-db-<id>`, both derived from the ID, so a rename never changes them. Labels: `relist.database.id` and `relist.database.hash`.
- **Network.** `relist-network` only, no published port, with the stable name `relist-db-<id>` and the readable alias `<slug>.db.internal` (skipped when the slug is not DNS-safe, as ADR-0014). Restart policy `unless-stopped`; json-file logs capped at 10m x 5 (ADR-0028).
- **Records.** The `databases` table (migration `00041`) is the source of truth. On panel start and before every Database operation, Reconcile compares the container (by the hash label over image, data path, env, command, healthcheck and limits; not the alias) with the record and recreates it on drift. A volume that is gone is never recreated silently: the status is `volume_missing`.
- **Engine drivers.** `internal/databases` has an `Engine` interface with one driver each for postgres (18, 17, 16), mysql (8.4), mariadb (11.8, 11.4) and redis (8, 7.4). Postgres 18 keeps its data under `/var/lib/postgresql`, older versions under `/var/lib/postgresql/data`.
- **Password.** 32 random bytes, base64url without padding, generated by the panel and stored in plain text, because the panel must show it and later use it. Revealing it is audited.
- **Pull exception.** Pulling the Engine image (Docker Hub official, pinned by tag, no login) is the fifth exception to "the panel never pulls an image itself", after the Scanner (ADR-0021), the panel image (ADR-0024), BuildKit (ADR-0028) and `registry:3` (ADR-0033). Tags, not digests, so Update image can pick up patch releases.
- **Reserved names.** The Compose policy refuses a Service that answers on `relist-network` to `relist-db-<n>` or `*.db.internal`.
- **Tools, in later phases.** Backups run `pg_dump` / `mysqldump` through `docker exec` in the Database's own container; the Query panel connects with Go drivers over `relist-network`.
- **Migration.** Database volumes always move with a server Migration, and the old host stops every Database after the Composes.

## Considered options

**A hidden Compose with `kind=database`.** Rejected: every Compose belongs to an Environment, so it needs a fake system Project, the Compose, Policy and Deployment pages need guards, and editable YAML can drift from what the panel believes the credentials and image are.

**Templates (as Easypanel and Dokploy).** Rejected: a template writes a Compose once and the panel forgets what it made, so it cannot offer backups or queries without setup.

## Consequences

- Docker cleanup treats Database volumes and images as owned by the panel and never offers them.
- Deleting a Database deletes its volume; phase 1 has no Backups, so the record goes too.
