# Commit message conventions

## Format

Conventional Commits, no scope: `type: subject`, e.g. `feat: add install bootstrap via docker compose`.

Common types used in this repo:

| Type       | Use for                                            |
| ---------- | --------------------------------------------------- |
| `feat`     | New ticket/feature work                             |
| `fix`      | Bug fixes, including code-review-finding fixups     |
| `chore`    | Housekeeping — e.g. "close ticket N" commits         |
| `refactor` | Restructuring with no behavior change                |
| `docs`     | Documentation-only changes                          |
| `test`     | Test-only changes                                   |

Subject is imperative mood, lowercase after the colon, no trailing period. A body is optional and follows the same conventions as before (bullet points for multi-part changes, prose for narrative context).
